Ultra Exif Reader v4.12 사용 매뉴얼
작성 기준: Ultra_exif_reader_v4.12.html (v4.11 기반 실제 생성 프롬프트 기록 판독 추가)
개정일: 2026-11-07 (이전 판: v4.11, 2026-11-03)
작성자: 야문 짱

v4.12 주요 변경 — 생성 노드가 기록한 실제 프롬프트 판독
- 번역기·LLM 노드 등을 거쳐 연결선으로 들어온 프롬프트는 실행 중에만 존재해서 이미지에 남지 않았습니다.
  그래서 이전 버전은 연결을 거슬러 찾은 변환 전 원문(예: 번역 전 한글)만 표시할 수 있었습니다.
- Ultra Qwen Image Editor + PiD v1.0.4, Ultra Image + PiD v1.0.2부터 노드가 실제로 모델에 넣은
  긍정/부정 프롬프트를 이미지 메타데이터 "ultra_generation_prompts" 항목에 기록합니다.
- v4.12는 이 기록을 읽어 Positive / Final CLIP에 실제 프롬프트(예: 번역된 영문)를,
  Original / Source에 변환 전 원문을 함께 표시합니다.
- Image Saver(Simple)로 저장한 PNG·JPEG·WebP 모두 지원합니다. JPEG·WebP의 EXIF 칸에 들어간 기록은
  카메라 정보나 프롬프트 문장으로 잘못 표시되지 않습니다.
- 기록의 노드 번호·종류가 현재 그래프와 맞을 때만 사용하며, 생성 노드가 여럿이면 저장 노드와
  가장 가까운 생성 노드의 기록을 고릅니다.
- 기록이 없는 기존 이미지는 v4.11과 똑같이 표시됩니다.

v4.11 주요 변경 — 영문 인터페이스 보완
- 영문 메뉴·안내·상태·오류 메시지 중 한글로 남던 문구를 폭넓게 점검하고 번역 누락을 보완했습니다.
- EXIF/AI 정보 패널, 미디어 미리보기 등에서 긴 영어 표현으로 탭·버튼이 잘리는 문제를 영문 전용 레이아웃으로 개선했습니다.
- 한국어 UI의 기존 배치와 메타데이터 분석 결과·원문 프롬프트는 유지합니다.
- 이미지 분석 및 번역 기능은 사용자가 실행할 때만 기존 방식으로 동작합니다.

이하에는 v4.11 및 그 이전 버전에서 도입된 기능 설명과 검증 기록도 포함됩니다.

v4.9에서 v4.10 핵심 변경 (최신 검증본 기준)
- 올인원 생성 노드(UltraImagePiD 및 다른 커스텀 생성 노드)의 모델명·텍스트 인코더·VAE 인식
  (저장된 이미지까지 이어진 경로 위의 생성 노드가 하나로 확정될 때만 선택)
- 모델 계열(model_family) 표시: 예) MOSS-Image · moss_image_sft_int8_convrot.safetensors
- PiD 업스케일 표시: PiD 출력이 실제로 저장된 경우에만 업스케일 칸에 PiD 모델·배율·샘플러·스텝 표시
- 와일드카드·LLM 프롬프트 노드의 seed가 실제 생성 seed로 잘못 표시되던 문제 수정
- Wan 비디오 VAE 로더(WanVideoVAELoader 등) VAE 인식
- workflow만 남은 파일에서 UltraImagePiD의 모델·샘플링·PiD·LoRA 인식 (이름 붙은 위젯 값 우선)
- 모호한 경우(후보 여러 개, 서로 다른 PiD 저장 등)에는 임의로 고르지 않고 비워 둠
- 기존 정상 검출값 보존을 우선합니다. 이전 v4.9 대비 427개 비교와 PiD 집중 반례 41개를 검사했습니다 (77절).
- 추가 보완: 생성 Parameters의 명시적 CLIP: 모델 파일을 텍스트 인코더로 검출합니다. 파일에 없는 Denoise 값은 만들지 않습니다 (16·21·77절).

4.2에서 4.3 핵심 변경 (계속 유지)
프롬프트 추출 정교화
zip 파일내의 영상 이미지 추출가능


============================================================
0. 먼저 읽기
============================================================

Ultra Exif Reader v4.11은 이미지와 영상 파일 안에 실제로 남아 있는 메타데이터를 읽어 정리하는 브라우저용 단일 HTML 도구입니다.

이 앱이 할 수 있는 일은 크게 다섯 가지입니다.

1) 카메라·스마트폰 사진의 EXIF 촬영 정보 확인
2) AI 생성 이미지의 프롬프트·모델·샘플러·시드·LoRA 등 확인
3) ComfyUI 이미지·영상의 workflow/prompt를 분석하여 실제 사용 경로를 중심으로 핵심 정보 정리
4) 생성 메타가 없는 이미지에서 Gemini, GPT, Ollama Vision을 이용해 이미지 생성용 영어 프롬프트 추정
5) ZIP 압축 파일 안의 이미지·영상을 꺼내 같은 방식으로 분석

중요한 전제:
- 앱은 파일 안에 남아 있는 정보만 읽을 수 있습니다.
- 웹 업로드, 메신저 전송, 리사이즈, 재저장, 영상 재인코딩으로 삭제된 메타는 복원할 수 없습니다.
- 이미지 분석 기능은 원본 프롬프트를 복원하는 기능이 아니라, 보이는 이미지를 바탕으로 새로운 프롬프트를 추정하는 기능입니다.

권장 브라우저:
- Microsoft Edge
- Google Chrome
- 최신 Chromium 기반 브라우저


============================================================
1. 버전별 핵심 기능
============================================================

[v4.10에서 추가·수정된 기능]

1) 올인원 생성 노드 모델 인식 (v4.9까지의 누적 개선 유지)
- 모델 로더와 샘플러가 한 노드에 합쳐진 커스텀 노드(예: Ultra Tools Image + PiD)의 모델·텍스트 인코더·VAE를 읽습니다.
- 노드 이름이 아니라 입력 칸 이름과 그래프 구조(저장된 이미지까지 이어진 경로, 생성 설정, 후보 개수)로 판정합니다. 자세한 내용은 64절을 참고하십시오.

2) 모델 계열 표시
- 노드에 model_family 값이 있으면 Model 칸 앞에 계열명을 붙입니다.
- 예: Qwen Image 2.1 · qwen_image_2.1_turbo_int8_convrot.safetensors

3) PiD 업스케일 상세 표시 및 이름 없는 위젯 복원
- PiD 업스케일이 켜져 있고 유효한 모델 파일이 지정되며 PiD 출력이 실제로 저장 경로에 연결된 경우에만 표시합니다. 검증된 배율·샘플러·스케줄러·스텝은 Upscale 칸에 추가합니다 (65절).

4) seed 오표시 수정
- 와일드카드 처리기나 LLM 프롬프트 노드가 자체 seed를 가지고 있을 때, 그 값이 이미지 생성 seed로 잘못 표시되던 문제를 고쳤습니다 (66절).

5) 커스텀 생성 노드 범용 인식
- transformer_name, dit_name, gguf_name, model_name, model 등 여러 이름의 모델 칸을 쓰는 커스텀 생성 노드도, 엄격한 조건을 모두 만족할 때 인식합니다 (67절).
- 조건이 애매하면 고르지 않습니다.

6) Wan 비디오 VAE 인식
- VAE 파일을 model_name 칸에 받는 VAE 로더(WanVideoVAELoader 등)의 VAE를 읽습니다 (34절).

7) workflow만 남은 파일의 UltraImagePiD 인식 및 PiD 상세 복원
- prompt 정보 없이 workflow만 저장된 JPEG/WebP 등에서도 UltraImagePiD의 모델, 샘플링 값, PiD, LoRA를 읽습니다. 이름 없는 검증된 구형 위젯 배열에서는 PiD 상세 설정도 복원합니다 (68절).
- 노드가 저장한 이름 붙은 위젯 값(widgets_values_named)을 우선 사용합니다.

[v4.3 이후 v4.9까지 반영되어 v4.10에 포함된 기능]

- ZIP 안전 한도와 ZIP 출처 표시 (69절)
- 생성 단계별 프롬프트 표시 (70절)
- 최종 CLIP 프롬프트 확인 불가 안내와 Original / Source 표시 (71절)
- Recovered / Unconfirmed 미확정 프롬프트 표시 (71절)
- MiniMax H3 영상 생성 정보 (72절)
- Qwen Image 2.1, MOSS-Image, AuraFlow 관련 노드 지원 (73절)
- 영상 요약 4줄 표시: File / Generate / Play / Process (74절)
- Civitai 생성 이미지 전용 카드 (75절)
- 클라우드 AI 서비스 파일명 감지 (76절)
- 키보드·터치 조작 (78절)

[v4.3에서 추가된 기능 (계속 유지)]

v4.3는 단순 버전 표기 변경이 아니라, 이미지 메타 추출과 파일 목록 사용성이 크게 보강된 배포판이었습니다.

1) ComfyUI 드래그 앤 드롭 방식에 가까운 이미지 메타 추출
- PNG뿐 아니라 JPEG/JPG와 WebP에서도 workflow, prompt, parameters 후보를 더 폭넓게 읽습니다.
- Image Saver, Image Saver Simple 등 여러 저장 노드가 만든 JPEG/WebP 메타를 처리합니다.
- workflow만 있고 prompt map이 없는 파일, prompt map만 있는 파일, parameters만 있는 파일을 각각 구분해 처리합니다.

2) ComfyUI 실제 사용 경로 우선 분석
- 최종 출력 노드에서 upstream으로 연결을 따라가며 사용된 모델, 프롬프트, LoRA, 샘플링 값을 우선합니다.
- muted, bypassed 노드와 선택되지 않은 switch 경로가 결과에 섞이지 않도록 방어합니다.
- 서브그래프와 문자열형 노드 ID도 일부 지원합니다.

3) Ideogram 이중 프롬프트 표시
- LLM이나 변환 노드에 입력된 자연어 원본 프롬프트와 실제 Ideogram에 전달된 최종 JSON 프롬프트를 따로 표시합니다.
- 최종 JSON이 실제 실행 프롬프트이며, 자연어 프롬프트는 그 출처로 표시됩니다.
- 시스템 프롬프트나 제어용 지시문은 일반 프롬프트 칸에 표시하지 않습니다.

4) 파일 목록 순서 변경
- 왼쪽 썸네일 항목을 클릭한 채 드래그하면 순서를 바꿀 수 있습니다.
- 다른 항목을 드래그하기 시작하면 그 항목이 즉시 활성화되어 오른쪽 정보가 함께 바뀝니다.
- 순서 변경 과정에서 이미 추출된 메타를 다시 분석하지 않습니다.

5) 사이드바 공간 최적화
- 파일추가, 선택삭제, 캐시비움, 전체삭제 버튼이 한 줄에 표시됩니다.
- 파일 수, AI 파일, 카메라 사진, 메타 없음 통계도 한 줄에 표시됩니다.

6) 메타 파서 안정화
- 중복·대소문자 변형 PNG 청크 처리
- 압축 메타 처리 (현재 제한 사항은 25절 참고)
- WebP 메타 크기 방어
- 손상된 JSON·중첩 JSON 깊이 제한
- LoRA 중복 검출 방지
- conditioning wire 참조 중복 제거
- WebUI의 개행 없는 Parameters와 구형 Hires. 표기 처리
- 중괄호/대괄호로 시작하는 가중치 프롬프트 보존

7) 카메라 사진 오감지 방지
- Google Camera, Google Photos 등의 Software 태그를 Gemini 생성 이미지로 잘못 표시하지 않도록 수정되었습니다.


============================================================
2. 실행 방법
============================================================

1) ZIP 압축을 풉니다.
2) Ultra_exif_reader_v4.12.html을 Edge 또는 Chrome으로 엽니다.
3) 왼쪽 드롭 영역에 이미지, 영상, ZIP을 끌어다 놓거나 파일추가 버튼을 누릅니다.
   드롭 영역 밖, 앱 화면 아무 곳에 놓아도 추가됩니다.
4) 분석이 끝나면 왼쪽 목록에서 파일을 선택합니다.
5) 오른쪽에서 미리보기, 핵심 정보, 프롬프트, 원본 메타를 확인합니다.

별도 서버 설치는 필요하지 않습니다.

단, 다음 기능은 외부 연결을 사용합니다.
- ExifReader와 pako 라이브러리 로드: jsDelivr CDN
- Gemini 이미지 분석: Google Gemini API
- GPT 이미지 분석: OpenAI API
- 번역: Google 번역 엔드포인트
- Ollama Vision: 사용자 PC의 localhost:11434

인터넷이 완전히 차단된 환경에서는 기본 바이너리 파서가 일부 동작하더라도 카메라 EXIF나 압축 PNG 메타 등 일부 기능이 제한될 수 있습니다.

3. 지원 파일 형식
============================================================

이미지:
- PNG
- JPG
- JPEG
- WEBP

영상:
- MP4
- WEBM
- MKV
- MOV
- M4V

압축:
- ZIP (안에 든 위 형식의 이미지·영상만 꺼내 분석, 69절)

이미지 분석 레이어 지원 형식:
- PNG
- JPG/JPEG
- WEBP

직접 지원하지 않는 대표 형식:
- GIF
- BMP
- TIFF
- HEIC/HEIF
- AVIF
- PSD
- RAW 카메라 파일
- JSON 단독 파일
- TXT 단독 파일
- ZIP 안의 ZIP (중첩 압축)
- 7z, RAR 등 ZIP 이외 압축 형식

주의:
- 확장자만 바뀐 파일은 실제 바이너리 시그니처를 확인해 가능한 경우 올바른 형식으로 처리합니다.
- 브라우저가 코덱을 지원하지 않는 MKV/MOV 파일은 메타 분석은 가능해도 영상 미리보기가 안 될 수 있습니다.


============================================================
4. 개인정보와 외부 전송
============================================================

기본 메타 읽기:
- 사용자가 추가한 파일은 브라우저 안에서 읽습니다.
- 기본 EXIF/AI 메타 분석을 위해 파일 전체를 별도 서버에 업로드하지 않습니다.

이미지 분석 기능:
- Gemini 또는 GPT를 선택해 분석 실행을 누르면 이미지 데이터와 분석 지시문이 해당 API 제공사로 전송됩니다.
- Ollama Vision은 로컬 Ollama 서버로 전송합니다.

번역 기능:
- 번역할 프롬프트 텍스트가 Google 번역 서비스로 전송될 수 있습니다.

API 키:
- 저장을 선택하면 브라우저 localStorage에 보관됩니다.
- HTML 파일 안에 API 키가 삽입되어 배포되는 구조가 아닙니다.
- 공용 PC에서는 저장하지 않는 것을 권장합니다.

GPS:
- 사진에 GPS가 들어 있으면 위도·경도·고도가 표시될 수 있습니다.
- 앱은 GPS를 삭제하지 않습니다.
- 사진 공유 전 반드시 GPS 탭을 확인하십시오.

5. 화면 구성
============================================================

화면은 왼쪽 사이드바와 오른쪽 상세 영역으로 나뉩니다.

왼쪽 사이드바:
- 앱 이름과 v4.12 배지
- 파일 드래그 앤 드롭 영역
- 파일추가 / 선택삭제 / 캐시비움 / 전체삭제
- 파일 수 / AI 파일 / 카메라 사진 / 메타 없음 통계
- 썸네일 목록
- 체크박스
- 개별 삭제 버튼
- 드래그 순서 변경
- ZIP에서 꺼낸 파일의 ZIP 배지와 출처 줄

오른쪽 상세 영역:
- 파일명과 간단한 상태
- 복사 버튼
- 이미지 또는 영상 미리보기
- 줌 조작
- 핵심 정보
- AI/카메라 모드 전환
- 프롬프트
- 원본 메타 / 디버그
- 메타 없는 이미지의 이미지 분석 버튼


============================================================
6. 왼쪽 상단 네 개 버튼
============================================================

화면의 버튼 문구는 붙여 쓴 형태(파일추가, 선택삭제, 캐시비움, 전체삭제)입니다.

[파일추가]
- 파일 선택 창을 엽니다.
- 여러 파일을 동시에 선택할 수 있습니다.
- ZIP 파일도 선택할 수 있습니다.

[선택삭제]
- 목록 체크박스로 선택한 파일만 제거합니다.
- 원본 디스크 파일은 삭제하지 않습니다.

[캐시비움]
- 현재 보고 있지 않은 영상 미리보기 캐시를 정리합니다.
- 목록과 분석 결과는 유지됩니다.
- 현재 활성 영상은 유지됩니다.

[전체삭제]
- 현재 앱에 추가된 모든 파일을 목록에서 제거합니다.
- Object URL, 영상 엘리먼트, 분석 큐와 관련 상태를 정리합니다.
- 원본 디스크 파일은 삭제하지 않습니다.
- 정밀 스캔 중인 영상이 있으면 전체삭제가 제한됩니다.


============================================================
7. 통계 표시
============================================================

파일 수:
- 현재 목록에 들어 있는 전체 항목 수입니다.

AI 파일:
- AI 생성 메타가 성공 또는 부분적으로 감지된 이미지와 영상 수입니다.

카메라 사진:
- 카메라/스마트폰 EXIF가 감지된 이미지 수입니다.

메타 없음:
- AI 생성 메타와 카메라 EXIF를 찾지 못한 파일 수입니다.

한 파일에 AI 메타와 카메라 EXIF가 동시에 있으면 혼합 파일로 취급될 수 있습니다.


============================================================
8. 파일 추가와 분석 큐
============================================================

여러 파일을 한 번에 추가하면 최대 3개의 분석 worker가 병렬로 처리합니다.

분석 결과는 작업 시작 순서를 기준으로 커밋되어 목록 순서가 불필요하게 뒤섞이지 않습니다.

안전장치:
- 분석 작업마다 고유 순서 번호를 사용합니다.
- 전체 삭제나 초기화 후 이전 worker 결과가 새 목록에 들어오지 않도록 analysisToken을 확인합니다.
- 같은 파일을 분석 중에 다시 추가해도 pending 키로 중복을 차단합니다.
- 분석 실패 파일도 오류 항목으로 정리되어 다른 파일 분석을 중단시키지 않습니다.

대용량 파일을 여러 개 넣으면 브라우저 메모리와 CPU 사용량이 증가할 수 있습니다.


============================================================
9. 중복 파일 방지
============================================================

앱은 파일명, 크기, 수정 시간, MIME 타입 등을 조합해 같은 파일이 반복 추가되는 것을 막습니다.

분석이 끝난 파일뿐 아니라 분석 대기·진행 중인 파일도 중복 검사를 합니다.

주의:
- 브라우저는 실제 전체 파일 경로를 제공하지 않습니다.
- 서로 다른 폴더의 파일이더라도 이름, 크기, 수정 시간이 같으면 중복으로 판단될 가능성이 있습니다.
- 중복 방지는 같은 파일을 실수로 여러 번 넣는 문제를 줄이기 위한 기능입니다.
- 이름과 크기가 같아도 수정 시간이 다르면 다른 파일로 취급합니다. 새로 생성한 결과물이 이전 파일과 이름·용량이 같아도 중복으로 막히지 않습니다.
- ZIP에서 꺼낸 파일은 ZIP 이름·크기·수정 시간과 ZIP 안의 전체 경로까지 함께 비교합니다. 그래서 ZIP 밖의 photo.png와 ZIP 안의 photo.png, 서로 다른 폴더의 같은 이름 파일이 충돌하지 않습니다.
- 이미 있는 파일을 다시 넣으면 그 파일이 선택되고 "이미 추가된 파일" 안내가 표시됩니다.


============================================================
10. 파일 목록 클릭과 드래그 순서 변경
============================================================

일반 선택:
- 썸네일 항목을 한 번 클릭하면 오른쪽 상세 정보가 바뀝니다.
- 이미 분석된 정보를 사용하므로 파일을 다시 읽지 않습니다.

순서 변경:
1) 이동할 썸네일 항목의 본문을 누른 채 드래그합니다.
2) 원하는 항목의 위쪽 또는 아래쪽에 놓습니다.
3) 목록 순서만 바뀝니다.

드래그 중 동작:
- 선택되지 않은 항목을 드래그하면 해당 항목이 먼저 활성화됩니다.
- 오른쪽 정보는 이미 캐시된 메타와 미디어를 이용해 즉시 바뀝니다.
- 드롭 후 메타 추출이나 파일 분석을 다시 실행하지 않습니다.

드래그가 시작되지 않는 영역:
- 체크박스
- 개별 삭제 × 버튼

주의:
- 목록 순서는 보기 편의를 위한 순서입니다.
- 메타 결과, 파일 내용, 통계 분류에는 영향을 주지 않습니다.


============================================================
11. 체크박스와 삭제
============================================================

체크박스는 상세 보기 선택과 별개입니다.

예:
- 파일 A를 오른쪽에 표시한 상태에서 B와 C만 체크할 수 있습니다.
- 선택 삭제를 누르면 B와 C만 제거됩니다.
- 활성 파일이 삭제되면 남은 목록에서 적절한 다음 항목을 자동 선택합니다.

개별 × 버튼:
- 해당 항목 하나를 즉시 제거합니다.
- 클릭이 목록 선택이나 드래그로 이어지지 않도록 분리되어 있습니다.

정밀 스캔 중인 영상은 작업 안전을 위해 삭제가 제한될 수 있습니다.


============================================================
12. 미리보기와 줌
============================================================

이미지와 영상 미리보기는 오른쪽 상단에 표시됩니다.

기본 조작:
- 미리보기 클릭: 줌 모드 전환
- 마우스 휠: 확대/축소
- 확대 상태에서 드래그: 화면 이동
- 줌 슬라이더: 배율 직접 조절
- 줌 초기화: 배율과 이동 위치 초기화

영상:
- 기본 브라우저 재생 컨트롤을 사용할 수 있습니다.
- 재생 컨트롤 영역에서는 줌 드래그와 충돌하지 않도록 일부 입력이 분리됩니다.

파일을 바꿀 때 이전 미디어 상태가 새 파일에 잘못 적용되지 않도록 줌과 렌더링 상태를 정리합니다.

13. 영상 캐시
============================================================

영상은 다시 선택할 때마다 새 video element를 만들면 느려질 수 있습니다.

v4.10은 최근 영상 미리보기 최대 3개를 캐시합니다.

캐시 동작:
- 최근에 본 영상은 기존 video element를 재사용합니다.
- 활성 파일을 바꿀 때 이전 영상은 일시정지됩니다.
- 캐시 한도를 넘으면 가장 오래 사용하지 않은 비활성 영상을 정리합니다.

캐시비움 버튼:
- 현재 보고 있지 않은 영상 캐시만 비웁니다.
- 파일 목록과 메타는 그대로 유지됩니다.
- 다시 영상을 선택하면 미리보기만 다시 준비됩니다.


============================================================
14. 파일 종류 자동 분류
============================================================

AI 이미지/영상:
- 생성 메타를 읽어 앱, 모델, 프롬프트, 샘플링 정보를 표시합니다.

카메라 사진:
- EXIF 촬영 정보가 감지된 사진입니다.

혼합 파일:
- AI 생성 메타와 카메라 EXIF가 동시에 있는 이미지입니다.
- 핵심 정보 영역에서 AI/카메라 버튼으로 전환할 수 있습니다.

메타 없음:
- AI 생성 정보와 카메라 EXIF를 찾지 못했습니다.
- 이미지라면 이미지 분석 버튼이 표시될 수 있습니다.
- 영상이라면 정밀 스캔 버튼이 표시될 수 있습니다.

파싱 오류:
- 파일을 읽는 과정에서 오류가 발생했습니다.
- 해당 파일만 오류 상태로 표시되고 다른 파일 사용은 계속 가능합니다.

15. 상단 상태 표시
============================================================

상단 또는 핵심 정보 헤더에는 다음 정보가 표시될 수 있습니다.

앱/도구:
- ComfyUI, WebUI, NovelAI, InvokeAI, Gemini 등 감지된 생성 환경

신뢰도:
- high, medium, low 등 감지 근거 수준

메타 상태:
- parsed: 구조화 파싱 성공
- partial: 일부 정보만 추출
- detected: 후보는 있으나 완전 파싱 실패
- no meta: 생성 메타 없음
- parse error: 분석 오류
- EXIF: 카메라 정보 감지
- 📍 GPS 포함: GPS가 들어 있는 카메라 사진

메타 없는 영상의 상태 표시:
- 생성정보 없음 / 메타 후보 감지 / 부분 추출 / 생성정보 추출 / 파싱 오류

참고:
- Software 태그의 일반 Google 문자열만으로 Gemini라고 판정하지 않습니다.
- Google Camera나 Google Photos 사진은 카메라 사진으로 유지됩니다.


============================================================
16. AI 핵심 정보 패널
============================================================

파일에 따라 다음 항목이 표시됩니다.

- Model / Checkpoint
- UNet
- Base Model
- Text Encoder / CLIP / T5 / UMT5
- VAE
- Sampler
- Scheduler
- Steps
- CFG / Guidance
- Seed
- Size / Resolution
- Denoising strength
- Clip skip
- Upscaler / Hires
- LoRA
- Video 정보
- Sampling Stages
- ComfyUI source/workflow 정보

표시되지 않는 항목은 파일에 없거나 현재 파서가 확정하지 못한 값입니다.

Text Encoder 칸:
- ComfyUI 로더·활성 생성 경로에서 확인된 텍스트 인코더와, 생성 Parameters의 명시적 CLIP: 모델 파일명을 읽습니다.
- Parameters의 CLIP: 는 확장자가 분명한 단일 모델 파일명일 때만 채택합니다. CLIP skip 값이나 일반 프롬프트 문장은 텍스트 인코더로 취급하지 않습니다.
- 저장된 비활성 엔진의 설정 이력에 들어 있는 clip 값은 현재 사용된 텍스트 인코더라고 추정하지 않습니다.
- Denoise는 Denoising strength/denoise 등 실제 저장된 값이 확인되는 경우에만 표시합니다. 없으면 공백으로 둡니다.

모델과 LoRA는 서로 다른 자원입니다. LoRA 이름이 모델명처럼 표시되지 않도록 분리해서 처리합니다.

Model 칸 표시 형식:
- "종류 · 파일명" 형태로 표시됩니다.
- 종류는 checkpoint, unet, gguf/unet, hf/diffusers, model 중 하나이거나, 노드에 model_family 값이 있으면 그 계열명입니다.
- 예: checkpoint · juggernaut.safetensors
- 예: MOSS-Image · moss_image_sft_int8_convrot.safetensors
- 파일명에서 폴더 경로(Moss\ 등)는 생략하고 파일 이름만 표시합니다.

Upscale 칸 표시 예:
- 4x_ultrasharp.pth
- PiD · pid_1.5_qwenimage_1024_to_4096_4step_int8_convrot.safetensors · 배율 1(x4) · lcm, simple · 4 steps
- 없음

VAE 칸:
- VAE가 여러 개 감지되면 영상용 VAE가 우선 표시되고 나머지도 함께 나열됩니다.
- VAE 정보가 없으면 "없음"으로 표시됩니다.


============================================================
17. 프롬프트 패널 기본 구조
============================================================

현재 화면의 프롬프트 블록 이름:
- Original / Source: 변환 전 원본 입력 프롬프트 (LLM·번역·와일드카드 등의 입력)
- Recovered / Unconfirmed: 파일에 남아 있지만 실행 연결이 확인되지 않은 프롬프트 (71절)
- Positive / Final CLIP: 실제로 모델에 들어간 최종 프롬프트
- Negative: 부정 프롬프트
- 생성 단계 1, 2 …: 단계별 프롬프트 (70절)

일반 AI 파일:
- Positive / Final CLIP
- Negative

원본과 최종이 같은 경우:
- 두 칸에 같은 글이 반복되지 않도록 Original / Source 한 칸에만 표시합니다.

Ideogram 등 변환 파일:
- Original / Source: 자연어 프롬프트
- Positive / Final CLIP: Ideogram JSON 또는 최종 실행 프롬프트
- Negative

각 블록에는 다음 기능이 있습니다.
- 문자 수 표시
- 개별 복사
- 개별 번역

상단 프롬프트 복사:
- 자연어 원본이 있으면 자연어 원본도 포함합니다.
- 최종 실행 프롬프트와 Negative를 함께 복사합니다.


============================================================
18. Ideogram 자연어 원본과 최종 JSON
============================================================

ComfyUI에서 자연어 프롬프트를 LLM 노드가 Ideogram용 구조화 JSON으로 바꾸는 workflow가 있습니다.

v4.10 표시 원칙:
- 자연어 입력은 출처/원본 프롬프트(Original / Source)로 별도 표시
- 최종 JSON은 실제 모델 입력으로 표시
- 둘 중 하나로 합치지 않음
- 시스템 프롬프트, JSON 변환 지시문, 제어 텍스트는 일반 프롬프트로 표시하지 않음

예:

Original / Source:
A woman standing near a window in a modern living room...

Positive / Final CLIP:
{
  "subject": "...",
  "scene": "...",
  "lighting": "..."
}

최종 JSON이 파일에 저장되지 않았다면:
- 자연어 원본은 Original / Source로 표시할 수 있습니다.
- Positive / Final CLIP 칸에는 "최종 CLIP 프롬프트 확인 불가" 안내가 표시됩니다 (71절).


============================================================
19. 프롬프트 우선순위
============================================================

같은 파일 안에 여러 프롬프트 후보가 있을 수 있습니다.

v4.10의 기본 우선순위:
1) ComfyUI prompt map에서 실제 연결된 프롬프트
2) workflow의 active path에서 찾은 프롬프트
3) WebUI/A1111 Parameters 문자열
4) 일반 JSON/EXIF/XMP 후보

이미 확정된 높은 우선순위 프롬프트는 단순히 더 길다는 이유로 낮은 우선순위 문자열에 덮어쓰지 않습니다.

이 원칙은 workflow와 parameters가 동시에 들어 있는 Image Saver 파일에서 잘못된 프롬프트 교체를 줄입니다.

20. 가중치 프롬프트와 구조화 JSON 구분
============================================================

다음과 같은 프롬프트는 정상 프롬프트로 보존됩니다.

{masterpiece:1.5}, best quality
[masterpiece:1.2], cinematic lighting

중괄호나 대괄호로 시작한다는 이유만으로 JSON으로 오인하지 않습니다.

반대로 다음처럼 실제 JSON 파싱이 가능한 객체/배열 문자열은 일반 Positive로 승격하지 않습니다.

{"prompt":"...","model":"..."}
["tag1","tag2"]

이 처리는 InvokeAI, SwarmUI, DrawThings 등 일반 generation object 파서 경로에도 적용됩니다.

23. ComfyUI active path 분석

ComfyUI workflow에는 테스트 노드, 비활성 노드, 사용되지 않은 프롬프트와 LoRA가 남아 있을 수 있습니다.

주요 원칙:

- samples, image, conditioning, model, clip, vae 연결 추적
- muted/bypassed 노드 제외

- 서브그래프 내부 연결 일부 처리

active path를 찾지 못한 경우에만 제한적인 전체 노드 fallback을 사용합니다.

출력 노드가 여러 개인 경우:
- 한 번 실행에 원본 저장(Image Saver)과 PiD 저장(Image Saver)이 함께 있으면, 두 파일에는 같은 생성 정보가 들어갑니다.

참고:

25. PNG 메타와 안전 제한
============================================================

읽는 PNG 청크:
- tEXt
- zTXt
- iTXt
- EXIF 관련 청크
- NovelAI stealth metadata

안전장치:
- 대소문자만 다른 중복 키 처리
- 같은 키의 잘못된 단순 문자열 결합 방지
- UTF-8로 저장된 tEXt(한글·중국어 프롬프트)는 UTF-8로 우선 해석하고, 실패하면 Latin-1로 해석
- NovelAI stealth 검사는 1,200만 픽셀(약 12MP)을 넘는 PNG에서 생략
- 알파 채널이 없는 PNG는 stealth 검사를 생략
- 이미 텍스트 청크에 생성 메타가 있으면 stealth 검사를 생략
- 남은 픽셀 비트보다 큰 길이 선언은 읽기 실패로 처리

정정:
- 이전 매뉴얼에 적힌 "압축 메타 입력 최대 약 2MB / 압축 해제 결과 최대 약 8MB / stealth payload 최대 약 2MB" 제한은 현재 코드에 별도 상한으로 들어 있지 않습니다.
- 8MB 상한은 WebP의 EXIF/XMP 메타 텍스트에 적용됩니다 (27절).
- 비정상적으로 큰 압축 메타가 든 PNG는 브라우저 메모리를 많이 쓸 수 있으므로, 출처가 불분명한 파일은 소량씩 확인하십시오.

너무 큰 PNG에서는 메모리 보호를 위해 일부 stealth 검사가 생략될 수 있습니다.

주의:

36. 이미지 분석 기능
============================================================

이미지 안에 생성 메타가 없더라도 보이는 내용을 기반으로 영어 프롬프트를 만들 수 있습니다.

실행 방법:
1) 메타가 없는 PNG/JPG/WebP를 선택합니다.
2) 오른쪽의 이미지 분석으로 프롬프트 추정 버튼을 누릅니다.
3) Gemini, GPT, Ollama Vision 중 하나를 선택합니다.
4) 필요한 경우 커스텀 지시어를 입력합니다.
5) 분석 실행을 누릅니다.
6) 결과를 복사하거나 번역합니다.

이 기능은 다음을 추정합니다.
- 주체
- 인물/사물
- 배경
- 구도
- 카메라 시점
- 조명
- 색감
- 스타일
- 질감
- 분위기

알 수 없는 것:
- 실제 seed
- 실제 sampler
- 실제 CFG
- 실제 LoRA
- 실제 모델 체크포인트
- 원본 프롬프트 원문

이미지 분석 창 동작:
- [현재 이미지 사용]: 목록에서 선택한 이미지를 분석창으로 다시 불러옵니다.
- [이미지 선택]: 다른 PNG/JPG/WebP를 고릅니다. 분석창의 미리보기 영역에 끌어다 놓아도 됩니다.
- [이미지 지우기]: 분석 이미지만 해제합니다. 결과·지시어·API 키는 유지됩니다.
- [초기화]: 이미지, 분석 결과, 커스텀 지시어를 지웁니다. API 키는 유지됩니다.
- [✕ 닫기]: 창만 닫습니다. 결과는 페이지를 새로고침하기 전까지 보관됩니다. 진행 중이던 분석은 취소됩니다.
- Esc 키로는 닫히지 않습니다. 실수로 결과를 잃지 않도록 상단 ✕ 버튼을 사용하십시오.

입력 제한 (메모리 보호):
- 이미지 분석용 파일은 80MB 이하
- 원본 해상도 6,400만 픽셀(64MP) 이하
- 전송 전 긴 변 1536px로 축소 (Ollama는 768px)
- 투명 영역이 있는 PNG/WebP는 PNG로, 그 외는 JPEG로 변환해 전송
- 이 제한은 이미지 분석 기능에만 적용되며, 일반 메타 읽기에는 적용되지 않습니다.

요청 시간 제한:
- Gemini / GPT: 60초
- Ollama: 180초

45. 메타가 안 읽히는 이유
============================================================

1) 생성 앱이 메타를 저장하지 않음
2) 저장 노드의 metadata 옵션이 꺼짐
3) SNS/메신저 업로드 과정에서 제거됨
4) 캡처 또는 스크린샷 파일임
5) 편집 프로그램에서 재저장함
6) PNG/JPEG/WebP 변환 과정에서 제거됨
7) 영상이 재인코딩됨
8) 앱이 파일 내부가 아닌 별도 DB/sidecar에 저장함
9) 커스텀 노드 구조를 현재 파서가 알지 못함
10) 파일 일부가 손상됨
11) prompt 정보 없이 workflow만 저장되었고, 그 workflow의 커스텀 노드 값을 순서만으로는 해석할 수 없음 (68절)

먼저 원본 메타/디버그를 확인하고, 영상이라면 정밀 스캔을 시도하십시오.


============================================================
46. 대용량 파일 주의
============================================================

영상:
- 대형 영상은 head/tail 안전 스캔을 사용합니다.
- 정밀 스캔도 매우 큰 영상에서는 샘플 방식으로 제한됩니다.

이미지:
- PNG/JPEG/WebP는 메타와 미리보기를 위해 파일 전체를 읽을 수 있습니다.
- 수백 MB 이상의 극단적으로 큰 이미지는 브라우저 메모리를 많이 사용할 수 있습니다.
- 초대형 이미지를 여러 개 동시에 추가하지 않는 것이 좋습니다.

브라우저가 느려지면:
- 불필요한 파일 삭제
- 캐시 삭제
- 탭 새로 열기
- 파일을 소량씩 분석

47. 손상 파일과 안전장치
============================================================

v4.10은 다음 방어를 포함합니다.

- JSON.parse try/catch
- 중첩 JSON 깊이 최대 8단계
- 순환 객체 seen 추적
- workflow 그래프 깊이/방문 수 제한
- WebP 메타 텍스트 8MB 제한
- WebP/JPEG 청크 길이 검사
- ZIP 안전 한도 (69절)
- NovelAI stealth 길이 검사와 12MP 상한
- 분석 초기화 이전 worker 결과 차단
- 오래된 worker가 새 파일 pending 상태를 지우지 않도록 token 검사

손상 파일은 해당 항목만 parse error 또는 no meta로 처리하는 것이 기본입니다.

48. 네트워크 오류와 CDN
============================================================

앱은 ExifReader와 pako를 CDN에서 로드합니다.

네트워크가 느리면:
- 초기 화면 표시가 늦어질 수 있습니다.
- 카메라 EXIF 또는 압축 PNG 메타 기능이 제한될 수 있습니다.

CDN 로드 실패 시에도:
- 일부 직접 PNG/JPEG/WebP 파서는 동작할 수 있습니다.
- 하지만 모든 기능이 보장되지는 않습니다.

완전한 오프라인 사용이 반드시 필요하다면 외부 라이브러리를 내장한 별도 배포판이 필요합니다. 현재 v4.11 배포본은 일반적인 인터넷 연결 환경을 기준으로 합니다.

49. 문제 해결 빠른 목록
============================================================

[파일이 추가되지 않음]
- 지원 확장자인지 확인
- 같은 파일이 이미 목록이나 분석 큐에 있는지 확인

[드래그 순서 변경이 안 됨]
- 체크박스나 × 버튼이 아닌 항목 본문을 드래그
- 너무 짧게 클릭하면 일반 선택으로 처리됨

[드래그한 파일과 오른쪽 정보가 다름]
- v4.10에서는 드래그 시작 시 해당 항목이 즉시 활성화됩니다.
- 오래된 버전을 열고 있지 않은지 상단 v4.12 배지를 확인하십시오.

[영상이 재생되지 않음]
- 브라우저가 해당 코덱을 지원하지 않을 수 있음
- 메타 분석과 재생 지원은 별개

[영상 생성 메타가 없음]
- 원본 파일인지 확인
- save_metadata 확인
- 정밀 스캔 시도

[Positive 또는 Negative가 이상함]
- 원본 메타 확인
- ComfyUI active path가 복잡할 수 있음
- 시스템 프롬프트나 제어 텍스트는 의도적으로 제외될 수 있음

[Ideogram 자연어는 보이는데 JSON이 없음]
- 최종 LLM 응답이 파일에 저장되지 않았을 수 있음
- “최종 CLIP 프롬프트 확인 불가” 안내 확인

[Google Camera 사진이 Gemini로 표시됨]
- v4.3 이후 배포본에서는 수정됨
- 브라우저 캐시가 아니라 열어 둔 오래된 HTML인지 확인

[이미지 분석 실행 안 됨]
- 이미지 형식 확인
- API 키 확인
- Ollama는 Vision 모델과 서버 상태 확인

[번역 실패]
- 잠시 후 재시도
- 구글 번역에서 열기 사용

[Model 칸이 - 로 나옴] (v4.10 보완)
- 모델이 커스텀 노드에 들어 있는 경우, 그 노드의 입력 칸 이름을 원본 메타에서 확인하십시오 (64·67절).
- 저장된 이미지 경로 위에 생성 노드가 2개 이상이거나, 서로 다른 모델을 가리키는 UltraImagePiD가 여럿이면 모호하므로 의도적으로 비워 둡니다.
- 별도 KSampler 같은 샘플러가 따로 연결된 워크플로우에서는 커스텀 노드 범용 인식을 하지 않습니다 (기존 로더 검출이 우선).
- prompt 정보 없이 workflow만 남은 파일이면 해석이 제한됩니다 (68절).

[저장 경로와 Model 계열이 다름]
- Model 칸은 파일에 기록된 생성 노드 설정을 그대로 표시합니다.
- 예: 저장 경로는 Image/Krea2인데 Model은 MOSS-Image로 나오면, 실제 생성 당시 노드 설정이 MOSS-Image였던 것입니다.

[Seed가 예상과 다름]
- 와일드카드·LLM 노드의 seed가 아닌 생성 노드의 seed를 표시합니다 (66절).
- 샘플러가 여러 개면 노드 번호 순서상 앞선 생성 노드 값이 표시될 수 있으니 Sampling Stages와 원본 메타를 함께 확인하십시오.

[PiD 이미지인데 Upscale이 없음]
- 해당 실행에서 pid_upscale이 꺼져 있었는지 원본 메타를 확인하십시오 (65절).
- PiD 출력(두 번째 출력, PiD Image)이 저장 노드까지 연결되어 있지 않으면 표시하지 않습니다.
- pid_model 값이 비어 있거나 확정된 모델 파일 이름이 아니면 표시하지 않습니다.
- 서로 다른 PiD 설정의 출력이 여러 개 저장된 실행은 모호하므로 표시하지 않습니다.

[ZIP을 넣었는데 추가되지 않음]
- ZIP 안에 지원 형식 파일이 있는지 확인
- 안전 한도 안내가 나왔다면 69절 확인
- ZIP64 형식(4GB 이상 등)의 항목은 건너뜁니다.

54. 메타데이터 소스별 해석 순서
============================================================

한 파일에는 같은 정보가 여러 위치에 중복 저장될 수 있습니다.

예:
- PNG parameters에 WebUI 프롬프트
- PNG workflow에 ComfyUI 그래프
- PNG prompt에 실행용 prompt map
- EXIF UserComment에 다시 저장된 Parameters
- XMP Description에 별도 설명문

v4.10은 모든 문자열을 단순히 합치지 않습니다. 정보의 성격과 신뢰도를 고려해 우선순위를 정합니다.

ComfyUI 계열:
1) 실제 실행 prompt map
2) active workflow 연결
3) workflow 내부 widgets_values/inputs
4) 저장 노드가 남긴 보조 필드
5) 일반 텍스트 fallback

WebUI 계열:
1) 완전한 Parameters 블록
2) Positive/Negative와 Steps 구간 분리
3) 개행 없는 손상형 Parameters 복구
4) 일반 EXIF/XMP 문자열 fallback

카메라 계열:
- Make, Model, LensModel, DateTimeOriginal, ExposureTime 등 표준 EXIF 태그를 우선합니다.
- Software 하나만으로 AI 생성 이미지라고 단정하지 않습니다.

중요:
- 더 긴 문자열이 항상 더 정확한 것은 아닙니다.
- 낮은 우선순위 후보가 더 길다는 이유로 이미 확정된 프롬프트를 덮어쓰지 않습니다.


============================================================
55. ComfyUI prompt map과 workflow의 차이
============================================================

prompt map:
- ComfyUI가 실제 실행을 위해 사용하는 노드 입력 구조입니다.
- 노드 ID를 키로 하고 class_type과 inputs를 포함하는 경우가 많습니다.
- 실행 당시의 구체적 입력값을 찾는 데 유리합니다.

workflow:
- ComfyUI 화면에서 노드 위치, 링크, 위젯 상태 등을 복원하는 그래프입니다.
- 사용자가 이미지를 ComfyUI에 드래그했을 때 화면 workflow를 복원하는 데 사용됩니다.
- 노드가 남아 있어도 실제 실행 경로에서 사용되지 않았을 수 있습니다.

v4.10의 해석:
- prompt map이 있으면 실행값 우선
- workflow는 링크 구조, 저장 노드, 서브그래프, 보조 정보 확인에 사용
- 둘이 모두 있으면 서로 보완하되 중복 정보를 무조건 두 번 세지 않음
- prompt map이 없고 workflow만 있으면 workflow-only 경로로 최대한 복원


============================================================
56. Conditioning과 Positive/Negative 추적
============================================================

ComfyUI에서는 프롬프트 텍스트가 항상 sampler에 직접 문자열로 연결되지 않습니다.

일반 흐름 예:
텍스트 노드 → CLIP Text Encode → Conditioning Combine → Sampler

v4.10은 다음 포트 이름과 연결을 참고합니다.
- positive
- negative
- pos
- neg
- conditioning
- conditioning_1 / conditioning_2
- cond_positive / cond_negative
- positive_conditioning / negative_conditioning
- positive_prompt / negative_prompt (올인원 생성 노드의 문자열 입력)

같은 wire가 여러 경로에서 반복 발견되어도 [nodeId, output slot] 값이 같으면 중복 탐색하지 않습니다.

주의:
- 사용자 정의 노드가 Positive/Negative 의미를 전혀 다른 포트명으로 숨기면 자동 구분이 어려울 수 있습니다.
- 두 conditioning이 있으나 이름으로 구분할 수 없으면 순서 기반 fallback이 사용될 수 있습니다.
- 결과가 의심스러우면 원본 workflow와 Debug를 함께 확인하십시오.


============================================================
57. muted, bypass, switch 처리
============================================================

workflow에는 다음 상태가 포함될 수 있습니다.
- 실행되는 일반 노드
- muted 노드
- bypassed 노드
- switch에서 선택되지 않은 입력
- 테스트용으로 남겨 둔 분기

v4.10은 가능한 경우 활성 경로만 추적합니다.

예:
- I2V LoRA와 T2V LoRA가 모두 workflow에 있지만 switch가 T2V를 선택했다면 T2V 경로를 우선
- 테스트 프롬프트 노드가 연결 해제되었으면 일반 Positive로 승격하지 않음
- bypass된 LoRA loader가 그래프에 남아 있어도 active LoRA로 표시하지 않도록 시도

한계:
- 커스텀 switch가 선택 상태를 비표준 방식으로 저장하면 완벽히 판별하지 못할 수 있습니다.
- 이 경우 전체 후보가 아니라 active path 우선 결과와 Debug를 비교하십시오.


============================================================
58. 시스템 프롬프트와 제어 문구 제외
============================================================

LLM 기반 workflow에는 실제 이미지 묘사 외에도 다음 텍스트가 포함될 수 있습니다.

- “다음 문장을 JSON으로 변환하라”
- “시스템 지시를 따르라”
- 출력 형식 템플릿
- 역할 설명
- 금지 규칙
- assistant/user 메시지 래퍼

v4.10은 이런 제어 텍스트를 실제 이미지 Positive로 표시하지 않도록 필터링합니다.

Ideogram의 경우:
- 사용자가 입력한 자연어 장면 설명은 source prompt
- LLM이 만든 최종 JSON은 실행 prompt
- 변환 규칙과 시스템 지시는 표시 제외

동적 출력이 파일에 남지 않은 경우에는 source prompt만 표시하고 “최종 CLIP 프롬프트 확인 불가”로 안내합니다.

============================================================
64. 올인원 생성 노드의 모델 인식 (v4.10)
============================================================

일부 커스텀 노드는 모델 로더와 샘플러를 하나의 생성 노드에 넣습니다.
예: Ultra Tools Image + PiD (노드 타입 UltraImagePiD).

기존 최종 v4.9에서 확인한 구조 기반 모델 검출을 그대로 유지합니다.
- 별도 CheckpointLoader/UNETLoader 등에서 확정된 모델을 우선합니다.
- 저장 출력으로 이어지는 실제 생성 경로를 따라가며 후보를 제한합니다.
- UltraImagePiD는 diffusion_model, text_encoder, vae_name, model_family를 읽습니다.
- 모델을 복수로 찾거나 별도 샘플러 때문에 판단이 모호하면 임의로 선택하지 않습니다.
- LoRA, PiD 업스케일 모델, 디테일러·보조 모델을 기본 모델로 잘못 승격하지 않습니다.
- 사용자 표시의 모델 계열(model_family)과 기본 모델 파일명을 구분합니다.

실제 예:
- Model: Qwen Image 2.1 · qwen_image_2.1_turbo_int8_convrot.safetensors
- Text Encoder: qwen3vl_8b_int8_convrot.safetensors
- VAE: qwen_image_2.1_vae_bf16.safetensors

이름에 Loader가 없는 다른 커스텀 생성 노드는 67절의 보수적 판정 규칙을 적용합니다.


============================================================
65. PiD 업스케일 모델 및 상세 정보 (v4.10)
============================================================

UltraImagePiD 안에는 아래 PiD 설정이 저장될 수 있습니다.
- pid_upscale: 활성화/비활성화
- pid_model: PiD 모델 파일명
- pid_output_scale: 출력 배율
- pid_sampler / pid_scheduler / pid_steps: PiD 전용 샘플링 설정

PiD 업스케일로 표시하는 필수 조건:
1) pid_upscale = true
2) pid_model이 실제 유효한 모델 파일명(.safetensors/.ckpt/.pt/.pth/.bin/.gguf 등)
3) UltraImagePiD의 출력 슬롯 1(PiD Image)이 저장 IMAGE 입력까지 연결됨
4) 저장된 PiD 모델 후보가 하나로 확인됨
5) 기존 다른 업스케일러 검출 결과가 없어서 덮어쓰기 위험이 없음

모델이 <auto PiD model> 같은 미확정 문자열이면 실행 시 사용된 정확한 파일명을 알 수 없으므로 PiD 업스케일 모델로 확정하지 않습니다.
PiD가 켜져 있어도 원본 출력(슬롯 0)만 저장했다면 PiD 업스케일로 표시하지 않습니다.

상세 정보 표시 조건:
- 위 필수 조건을 통과하고 저장에 사용된 PiD 생성 노드가 하나로 특정되어야 합니다.
- 배율·PiD Sampler·Scheduler·Steps가 모두 유효한 값일 때만 세부 항목을 함께 표시합니다.
- 세부 값이 부족하거나 의심스러우면 기존 v4.9와 동일하게 모델 파일명만 표시합니다.
- PiD Sampler(lcm)와 Steps(4)는 메인 생성 Sampler·Steps를 덮어쓰지 않습니다.

화면의 Upscale 표시 예:
PiD · pid_1.5_qwenimage_1024_to_4096_4step_int8_convrot.safetensors · 배율 1(x4) · lcm, simple · 4 Steps

출력 연결은 PiD Image → 워터마크/이미지 후처리(있다면) → Save Image 등 실제 IMAGE 선을 따라 확인합니다.
LoRA·MASK·설정 입력에서 나온 참조 선을 PiD 출력 연결로 간주하지 않습니다.

동일한 생성 실행에서 원본 출력과 PiD 출력을 각각 저장하면 파일마다 같은 workflow/prompt 메타가 실릴 수 있습니다.
이 경우 개별 파일의 실제 PiD 적용 여부를 메타데이터만으로 완벽히 판별하지 못할 수 있으므로 실제 이미지 해상도도 함께 확인하십시오.

66. Seed 우선순위 (기존 v4.9 개선 유지)
============================================================

와일드카드·LLM 프롬프트 노드의 자체 seed는 문장 생성용이며 실제 이미지 생성 seed와 다릅니다.
기존 최종 v4.9에서 이 오표시를 수정했고 v4.10에서도 동일한 우선순위를 유지합니다.
- KSampler/실제 생성 노드의 seed를 우선합니다.
- 동적 프롬프트 전용 노드의 seed는 생성 seed를 덮어쓰지 않습니다.
- 여러 실행 경로가 모호하면 원본 메타/샘플링 단계도 확인하십시오.

이번 v4.10의 PiD 상세 표시 기능은 Seed·Sampler·CFG·Steps 기본 검출 순서를 변경하지 않았습니다.

67. 다른 커스텀 생성 노드의 보수적 모델 인식
============================================================

새 v4.10은 최종 v4.9의 검증된 범용 모델 검출을 보존합니다.

기본 모델 복원은 아래 조건에서만 실행합니다.
1) 기존 모델 검출 결과가 비어 있고 실제 저장 출력이 확인됨
2) 생성 노드가 저장 IMAGE 계열 경로에 연결됨 (보조 설정/미리보기 분기와 구분)
3) seed, steps, sampler 값의 생성 계약을 갖춘 노드임
4) 기본 모델로 해석 가능한 파일명 입력이 하나만 확인됨
5) LoRA, 업스케일, 디테일러, 검출기, 보조 모델 노드가 아님
6) 후보 생성 노드가 하나만 존재하고, 별도 실행 샘플러와 충돌하지 않음

후보 모델 키 예:
- diffusion_model, diffusion_model_name, unet_name, ckpt_name
- checkpoint_name, model_name, base_model, transformer_name, dit_name
- gguf_name, model_file, model_path, model

서로 다른 모델 후보를 뜻할 수 있는 필드가 복수 존재하는 경우 임의로 첫 번째 모델을 고르지 않습니다.
model/vae 등 일반적인 키도 단일 생성 노드의 확실한 경로·파일 형식을 확인한 경우에만 보충합니다.
기존에 검출한 모델이나 VAE를 새 후보로 덮어쓰지 않습니다.

68. workflow만 남은 파일의 UltraImagePiD 해석 (v4.10)
============================================================

ComfyUI prompt map이 제거되고 workflow만 남은 파일은 노드 위젯 값이 이름 없는 배열로 기록될 수 있습니다.

해석 우선순위:
1) widgets_values_named가 있으면 해당 이름으로 읽습니다. 순서를 바꾸어도 이름값을 우선합니다.
2) 이름 붙은 데이터가 없는 UltraImagePiD에서는 알려진 구형 위젯 배열만 위치 기반으로 읽습니다.
3) 기본 모델·생성 설정의 값 형식과 배열 위치가 확인된 경우에만 복원합니다.
4) PiD 상세 복원은 더 엄격하게, 활성화 여부/모델 파일/샘플러/스케줄러/Steps/배율 및 주변 위젯 위치·자료형까지 확인합니다.
5) 배열이 불완전하거나 순서가 변한 것으로 보이면 PiD 상세를 추측하지 않습니다.

중요 보호 규칙:
- 무효화된(muted/bypassed) 노드는 제외합니다.
- 워터마크 블렌드 모드(normal) 또는 PiD 전용 lcm이 메인 샘플러로 잘못 표시되지 않게 합니다.
- PiD 업스케일 여부는 반드시 출력 슬롯 1 → 실제 저장 경로 연결로 다시 검사합니다.
- 다른 커스텀 생성 노드는 이름 없는 위젯 배열을 무턱대고 해석하지 않습니다.

모든 과거/미래 노드 버전의 위젯 순서까지 자동으로 해석하는 기능은 아닙니다.
가장 정확한 원본 보관을 위해 prompt와 workflow가 모두 저장된 PNG를 권장합니다.

69. ZIP 파일 처리
============================================================

ZIP을 추가하면 안에 든 PNG/JPG/JPEG/WebP/MP4/WebM/MKV/MOV/M4V만 꺼내 분석합니다.

목록 표시:
- 파일명 옆에 ZIP 배지가 붙습니다.
- 그 아래 줄에 "ZIP: 원본.zip › 내부경로/파일명"이 표시됩니다 (긴 경로는 가운데를 줄여 표시).
- 마우스를 올리면 전체 경로가 보입니다.
- 오른쪽 상단 파일명에도 ZIP 배지가 표시됩니다.

지원 압축 방식:
- 저장(무압축), Deflate
- 그 외 압축 방식과 ZIP64 항목은 건너뜁니다.
- 파일명 인코딩은 UTF-8을 우선하고, 실패하면 다른 방식으로 해석합니다.

안전 한도 (브라우저 메모리 보호):
- ZIP 파일 크기: 256MB 이하
- ZIP 안 전체 항목 수: 4,096개 이하
- ZIP 안 지원 파일 수: 256개 이하
- ZIP 안 파일 하나의 풀린 크기: 384MB 이하
- 지원 파일들의 풀린 크기 합계: 512MB 이하
- 압축률이 비정상적으로 높은 파일(압축 폭탄 의심): 차단
한도를 넘으면 ZIP 전체가 추가되지 않고 이유가 안내됩니다.

기타:
- 같은 ZIP을 처리하는 중에 다시 넣으면 "같은 ZIP 파일을 이미 처리 중" 안내 후 무시합니다.
- ZIP 안에 지원 파일이 없으면 "ZIP 안에서 지원 파일을 찾지 못했습니다" 안내가 나옵니다.
- 중복 판정은 9절을 참고하십시오.

70. 생성 단계별 프롬프트 표시
============================================================

하나의 출력에 여러 생성 단계가 이어진 워크플로우가 있습니다.
예: 1단계로 만든 이미지를 2단계 생성의 입력으로 다시 사용

표시 조건 (모두 만족할 때만):
1) 현재 파일을 만든 출력 경로가 하나로 확정됨
   (저장 형식·확장자가 맞는 저장 노드가 하나, 또는 저장 노드가 하나뿐)
2) 각 단계가 서로 연결된 하나의 흐름임 (독립된 여러 분기는 합치지 않음)
3) 각 단계의 텍스트 조건이 메타데이터에서 실제 문자열로 확인됨

표시 형식:
- 생성 단계 1, 생성 단계 2 … 카드
- 각 카드 안에 Positive / Negative / 텍스트 조건 칸
- 상태 배지: 확정 / 부분 확인 / 없음 / 미검출
- 각 칸마다 번역·복사 버튼

같은 프롬프트가 반복되는 경우:
- 여러 샘플러가 똑같은 프롬프트를 공유하면 단계 카드를 반복하지 않고 일반 표시(Original / Positive / Negative)를 사용합니다.

조건을 만족하지 않으면 기존 방식의 단일 프롬프트 표시를 사용합니다.

71. 최종 CLIP 확인 불가와 미확정 프롬프트
============================================================

[최종 CLIP 프롬프트 확인 불가]
- 원본 프롬프트가 번역·LLM·변환 노드를 거쳐 CLIP에 들어갔는데, 그 노드의 실행 결과 문자열이 파일에 저장되지 않은 경우입니다.
- 이때 변환 전 입력은 Original / Source로 표시하고, Positive / Final CLIP 칸에는 확인 불가 안내를 표시합니다.
- 변환 전 입력을 최종 프롬프트처럼 표시하지 않기 위한 처리입니다.
- 변환 노드 바로 아래에 같은 출력을 그대로 보여주는 TextBox/Display 노드가 있고 그 노드가 실행 결과를 저장했다면, 그 값을 최종 프롬프트로 사용합니다.

[Recovered / Unconfirmed]
- 파일 안에 생성 프롬프트로 보이는 문자열이 남아 있지만, 저장된 실행 정보에서 실제 연결이 확인되지 않은 경우입니다.
- 현재는 MiniMax H3 Ref2VA처럼 H3 노드의 prompt 칸이 비어 있고 연결도 없는 영상에서 표시됩니다.
- "미확정" 정보이므로 참고용으로만 사용하십시오.

78. 키보드·터치 조작
============================================================

키보드 (입력 칸에 커서가 없을 때):
- ↓ : 목록의 다음 파일 선택
- ↑ : 목록의 이전 파일 선택
- Delete / Backspace : 현재 선택한 파일을 목록에서 제거 (원본 파일은 삭제되지 않음)
- Esc : 번역 창 닫기

터치 (태블릿·터치스크린):
- 두 손가락 벌리기/모으기 : 미리보기 확대/축소
- 확대 상태에서 한 손가락 드래그 : 화면 이동
- 원래 크기로 돌아오면 줌 모드가 자동 해제됩니다.

좁은 화면:
- 화면 폭이 좁으면 목록이 위쪽으로 이동하고 2열 또는 1열로 바뀝니다.
- 번역 창은 아래쪽 시트 형태로 표시됩니다.

79. KO / EN 사용자 인터페이스 전환 (v4.10 추가)
============================================================

화면 좌측 상단 "Ultra Exif Reader  v4.12" 제목의 오른쪽에 KO / EN 전환 버튼이 있습니다.
- KO: 한국어 화면 (최초 실행 기본값)
- EN: 영어 화면
- 선택 언어는 브라우저 localStorage (ultra_exif_reader_ui_language_v410)에 기억됩니다.
- 일반적인 버튼, 탭, 패널 제목, 도움말, 이미지 분석 창의 안내문 등 화면 표시 문구만 전환합니다.
- 파일을 다시 분석하거나 메타데이터를 다시 읽지 않습니다.
- 파일명, 원본 프롬프트, 분석 결과, 원본 메타데이터, 모델·VAE·LoRA 파일명, Seed, Steps 등 실제 저장값은 번역하거나 바꾸지 않습니다.
- 원문 그대로인 영어/한국어 프롬프트, 번역 결과, 사용자 지시문과 API 키 값은 표시 언어와 무관하게 보존합니다.
- 프롬프트의 '번역' 버튼은 기존 기능 그대로 한국어 번역을 수행합니다. 화면 EN을 눌렀다고 영문 프롬프트 번역 언어가 바뀌지는 않습니다.
- 언어를 바꾸어도 파일 목록, 현재 미디어, 카메라·분석 결과, 파일 선택, 줌·영상 재생 상태를 초기화하지 않습니다.
- 브라우저에서 저장소 사용을 제한하는 경우 언어 선택이 다음 실행에 기억되지 않을 수 있습니다.
- 화면 너비가 좁으면 제목과 언어 버튼의 간격이 자동으로 조절됩니다.

English:
Use the KO / EN segmented control next to the v4.12 badge to switch the interface language.
KO is the default. The preference is saved locally when browser storage is available.
Switching the language does NOT reprocess files or modify extracted metadata, filenames,
original prompts, model identifiers, API keys, image analysis results, or translation targets.
The existing Translate buttons continue to translate prompts to Korean.

v4.10 KO/EN 검증 범위:
